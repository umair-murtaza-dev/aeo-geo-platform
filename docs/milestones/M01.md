# Milestone M01 — Foundation

STATUS: PARTIAL

M01 is the repository, schema, contract, and runtime foundation. Product features from M02 onward are not implemented. This file records what was built and what was actually executed on 2026-10-18.

## Scope

- pnpm and Turborepo monorepo for `apps/web`, `apps/api`, and `apps/worker`.
- Shared Zod contracts, permission matrix, and API error codes.
- Canonical Prisma schema and an unapplied SQL migration.
- Express foundation under `/api/v1`, including health and readiness.
- Auth.js session on Next.js and a separate bearer token for Express.
- BullMQ worker shell with a harmless ping job.
- Mock AI provider adapter for contract tests.
- Parallel-development ownership and contract documents.
- GitHub Actions workflow. It has not been executed on GitHub.

## Implemented components

- Monorepo tooling: TypeScript 5.9.3, ESLint 10, Prettier, Vitest, Tailwind CSS 4, shadcn-style components in `packages/ui`.
- Next.js App Router pages: home, login, dashboard, loading, error, and not-found.
- Express routes that exist in code: `GET /health`, `GET /ready`, `GET /api/v1/health`, `GET /api/v1/ready`, `GET /api/v1`, `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/me`, `GET /api/v1/organizations`, `POST /api/v1/organizations`, `GET /api/v1/organizations/:organizationId`, `GET /api/v1/organizations/:organizationId/workspaces`.
- Prisma models for users, Auth.js accounts, organizations, workspaces, brands, monitoring evidence, audits, experiments, reports, plans, and audit logs. See `docs/architecture/database-erd.md`.
- Permission checks in `@aeo/shared` and tenant denial tests against the in-memory store.
- Worker queues `system.ping` and `monitoring.execute`. The monitoring processor returns `deferred` and does not call a provider.

## Deferred features

- Real AI provider calls, observation persistence jobs, visibility calculations, audits, experiments, report rendering, and Stripe billing.
- HTTP routes for those areas. They are documented contracts and return `404` if requested.
- OAuth providers. Credentials (email and scrypt password hash) are the M01 identity flow. `PrismaAdapter` is wired when a Prisma client exists so a later OAuth provider can use the same user tables.
- Playwright execution in this environment. The spec is `apps/web/e2e/smoke.spec.ts`.

- `@aeo/worker`: ping job, idempotency, and a Redis integration test that obliterates only its own prefix.

Playwright was not executed here. Chromium was not installed in this session. The home and login pages were opened in a browser against `next start`. The home page states that no sample metrics are shown. The login page shows both forms. Opening `/dashboard` without a session redirected to `/login`.

A later `pnpm db:check` with `DATABASE_URL` unset printed that the connection was not attempted. An earlier probe used a shell-only placeholder URL so `prisma validate` could parse the schema. That probe was denied by the local server and did not migrate. The placeholder was then removed from the process environment. It was never a Neon credential and it is not in the repository.

## Known limitations

- There is no approved empty Neon database, so tables do not exist yet.
- The Prisma integration test has not run against Postgres.
- GitHub Actions has not run.
- The API production bundle is CommonJS (`dist/index.cjs`) because Prisma's client uses `require` and the ESM bundle could not load it. `pnpm --filter @aeo/api dev` still uses `tsx`.
- Library packages typecheck without emitting files. Turborepo reports "no output files" for those builds. The tasks still succeed.
- Agency roles can read every workspace in their organization. Client viewers cannot. That choice is explicit in ADR-004.
- `currentVersionId` on a prompt is a pointer without a foreign key, so a version row can exist before it is marked current.

## Future migration risks

- Applying `20261018120000_init` to a non-empty database can fail or, if someone later uses a reset, destroy data. Apply it only to an empty database this project owns.
- Moving to Prisma 7 changes how `DATABASE_URL` and `DIRECT_URL` are configured. Do that with the Auth.js adapter in the same change.
- Adding a foreign key from `monitoring_prompts.current_version_id` to `prompt_versions` needs a two-step migration because the version row also points at the prompt.
- Partial unique indexes and the brand-mention check constraint are raw SQL appended to the migration. Prisma schema edits will not regenerate them. Keep them in the next migration if the tables are rebuilt.
