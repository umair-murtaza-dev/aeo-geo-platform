# Milestone M01 — Foundation

STATUS: PARTIAL

Neon connectivity was attempted on 2026-10-18. The configured URL is a pooled Neon Postgres URL for database `neondb` in `us-east-2`, which matches the intended development database. Neon rejected the password. `pnpm db:check` and `pnpm db:migrate:status` both stopped with an authentication error. No migration was applied, and no tables were inspected, dropped, or truncated. The Prisma schema defines 38 models. Live foreign keys and check constraints were not verified because the session could not query the database.

M01 is the repository, schema, contract, and runtime foundation. Product features from M02 onward are not implemented. This file records what was built and what was actually executed on 2026-10-18.

## Test evidence

`pnpm validate` (`pnpm db:generate && turbo run lint typecheck test build`) completed with 40 successful tasks. 51 tests passed and 1 was skipped. The skipped test is the Prisma store test, which requires `TEST_DATABASE_URL`.

An earlier run, before the Neon URL was present, reported 47 passed and 1 skipped. The additional passing tests cover Postgres URL normalization: `postgresql` only, removal of `channel_binding`, and derivation of the direct migration host.

Observed test files during that run:

- `@aeo/shared`: permissions, access token, contracts, repo safety.
- `@aeo/api`: health, readiness, register, login, organization create, cross-tenant denial, CORS, unknown route.
- `@aeo/worker`: ping job, idempotency, and a Redis integration test that obliterates only its own prefix.
- `@aeo/db`: password hashing, memory store, and Postgres URL normalization. The Prisma store test was skipped because `TEST_DATABASE_URL` was unset. It was not pointed at the Neon development database.
- `@aeo/ai-providers`: mock adapter contract.
- `@aeo/analytics`, `@aeo/experiments`, `@aeo/reporting`: `NOT_IMPLEMENTED` guards.
- `@aeo/ui` and `@aeo/web`: utility and navigation unit tests.

Playwright was not executed here. Chromium was not installed in this session. The home and login pages were opened in a browser against `next start`. The home page states that no sample metrics are shown. The login page shows both forms. Opening `/dashboard` without a session redirected to `/login`.

`pnpm db:check` against the local `.env` printed the pooled host, database `neondb`, region `us-east-2`, and `sslmode=require`. It then exited 1 with `reason=authentication`. The command output did not include the password or the connection string. `pnpm db:migrate:status` used the derived direct host and exited with Prisma `P1000`. Neither command listed tables or migration history.

Prisma 6.19.3 treats a Neon URL that includes `channel_binding=require` as an unreachable server. Application code removes that parameter and sets a 20 second connect timeout before opening a client. Migrations go through `pnpm db:migrate:deploy`, which uses `DIRECT_URL` and refuses a pooled host, `migrate reset`, drop, and truncate.

## Known limitations

- Neon rejected the configured password, so it is unknown whether `neondb` is empty. The init migration stays unapplied until a real password is in `.env` and `pnpm db:check` shows zero public tables.
- The Prisma integration test has not run against Postgres. Docker was not available for the disposable database on port 54329.
- GitHub Actions has not run.
- The API production bundle is CommonJS (`dist/index.cjs`) because Prisma's client uses `require` and the ESM bundle could not load it. `pnpm --filter @aeo/api dev` still uses `tsx`.
- Library packages typecheck without emitting files. Turborepo reports "no output files" for those builds. The tasks still succeed.
- Agency roles can read every workspace in their organization. Client viewers cannot. That choice is explicit in ADR-004.
- `currentVersionId` on a prompt is a pointer without a foreign key, so a version row can exist before it is marked current.

## Future migration risks

- Applying `20261018120000_init` to a non-empty database can fail or, if someone later uses a reset, destroy data. Apply it only to an empty database this project owns.
- Moving to Prisma 7 changes how `DATABASE_URL` and `DIRECT_URL` are configured. Do that with the Auth.js adapter in the same change.
- Adding a foreign key from `monitoring_prompts.current_version_id` to `prompt_versions` needs a two-step migration because the version row also points at the prompt.
- Partial unique indexes and the brand-mention check constraint are raw SQL appended to the migration. Prisma schema edits will not regenerate them. Keep them in the next migration if the tables are rebuilt.
